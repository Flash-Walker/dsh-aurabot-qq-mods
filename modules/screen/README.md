# 手机屏幕（screen）

让她在主人的鸿蒙手机（HarmonyOS NEXT / 5 / 6 / 7）上长出一双手：用系统命令开应用、点、滑、打字、按键，
按需看一眼画面或读界面文字。更进一步：说一句「去玩十分钟手机」，她真的会自己玩满十分钟，然后回来汇报。

底层走 **hdc**（HarmonyOS Device Connector，鸿蒙版的 adb）。鸿蒙没有 adb，hdc + 设备端
`uitest` / `aa` / `bm` / `power-shell` 就是官方那套能力。

## 需要什么

| | |
|---|---|
| 插件 | Aurabot ≥ 1.2.0（扩展接口 v1） |
| 电脑 | 装了 hdc：DevEco Studio / Command Line Tools 里的 `hdc.exe`；留空会自动找 |
| 手机 | 开发者模式 + USB 调试打开，插上后 `hdc list targets` 能看到设备 |
| 账号 | 只有**主人私聊**能用这套工具，群友拿不到手机 |

## 怎么用

装好模块后在面板「已安装」页看到「手机屏幕」，把 `hdc` 路径填上（或者留空让它自己找）。

主人私聊里可以直接说人话：

- 「看一眼我手机现在什么界面」→ 截图发到聊天里
- 「把抖音打开」→ 默认一条命令 `aa start` 直接拉起，几秒就到；不行才退回点图标/搜索
- 「把抖音关掉」→ 一条 `aa force-stop`
- 「帮我点一下那个搜索框，输入天气」→ 读界面 → 点 → 打字
- 「去玩十分钟手机」→ 她去玩，十分钟后回来汇报
- 「别玩了」→ 立刻回桌面

也支持手打命令（只认主人）：

```
/手机                  截图
/手机 状态              连接 / 型号 / 前台应用 / 玩到第几步
/手机 桌面              回桌面
/手机 开 抖音           命令打开应用（后缀「像人」= 走点图标的老路子）
/手机 停 抖音           命令停掉这个应用
/手机 玩 10 抖音        去玩十分钟抖音（后缀「像人」= 演示档）
/手机 停               停止自动玩
```

## 她拿到的工具

| 工具 | 干什么 |
|---|---|
| `screen_see` | 截图并发到聊天里 |
| `screen_layout` | 把当前界面读成文字清单（`序号. 文字 [可点] @坐标`），可按关键词过滤 |
| `screen_tap` | 点：按文字、按清单序号、或按比例坐标 |
| `screen_swipe` | 上/下/左/右滑，可连滑、可快滑 |
| `screen_type` | 往输入框打字（可先点坐标） |
| `screen_key` | Back / Home / Power / KeyCode |
| `screen_open` | 打开 App（`via`: auto / command / human） |
| `screen_app` | **新**：`start / stop / restart / state`，走系统命令，一条命令就开/关/查前台 |
| `screen_status` | 连接、型号、系统版本、前台应用、自动玩进度 |
| `screen_play` | 自己去玩一段时间，到点回来汇报（`mode`: fast / human） |
| `screen_stop` | 立刻停止并回桌面 |

## 命令优先：能用命令就不动手

鸿蒙上有等价命令的操作，一律命令办，不再模拟人手：

| 想干的事 | 命令 | 备注 |
|---|---|---|
| 打开 App | `aa start -b <包名> -a <入口>` | 入口不知道就问系统：`bm dump -n <包名>` 里读（设备上先 grep，避免 63KB 全传） |
| 关掉 App | `aa force-stop <包名>` | 只作用于本模块这次开过的 App，或主人点名的那一个 |
| 回桌面 / 返回 / 亮屏 | `uitest uiInput keyEvent Home\|Back`、`power-shell wakeup` | |
| 往输入框打字 | `uitest uiInput inputText x y <文字>` | 低版本设备退回「点坐标 + 输入」 |
| 清应用数据 | **没有等价命令** | `bm uninstall` 会连包一起删，本模块**不做**，需要时请自己动手 |

这么做省下的是三样东西：时间（一条命令 1~3 秒 vs 点图标/翻屏/搜索 30 秒）、token（不用为目标界面反复读屏）、
以及不确定性（视觉错位、系统弹窗、控件树被盖住这些坑直接绕过）。

实测数据（JUY-AL50 / OpenHarmony-7.0.0.111）：

- 命令开抖音：`aa start -b com.ss.hm.ugc.aweme -a MainAbility`，约 3.5 秒到前台；
- 命令开快手（入口不在表里）：问 `bm dump` 学到 `EntryAbility` 后 **807ms**；不学的话退回下拉搜索要 31.5 秒；
- 命令停抖音：`aa force-stop` 约 1.4 秒，前台立刻让出去；
- 裸包名 `aa start -b com.kuaishou.hmapp` 会报 `Error Code:10103101`（implicit launch 找不到入口），所以入口必须带。

## 两种模式

| 模式 | 打开 App 的方式 | 什么时候用 |
|---|---|---|
| `fast`（默认） | 先命令，失败才点图标/搜索 | 日常 |
| `human` | 先点图标 → 翻屏 → 下拉搜索，都失败才用命令 | 演示「像人一样玩手机」、或面板里关掉「优先用命令开应用」 |

面板里关掉 `preferCommandOpen` 或给 `screen_open` / `screen_play` 传 `mode: 'human'` 就切到演示档。

## 「去玩十分钟」是怎么跑起来的

一轮 QQ 对话等不了十分钟，所以 `screen_play` 是**模块里的后台会话**，不占对话：

1. 用命令把 App 打开（失败才退回桌面点击/搜索）；
2. 之后每 `stepMs`（默认 4.5 秒）问一次模型「接下来做什么」，**一次可以给 1~3 个连贯动作**，
   本地连着执行完再问下一轮；
3. **不是每步都看屏幕**：每 `dumpEvery`（默认 3）个动作才读一次控件树，而且只给它
   「和上一帧的差异 + 最多 24 条可点条目」。开/停/回桌面/滑/等/按键这些动作完全不读屏；
4. **结束只看钟**：预算 = 开始时间 + 时长 − 20 秒收尾。她想提前收工（`done`）会被无视
   （剩余时间还多、或步数太少时），最多容忍 2 次；到点才停，回桌面，用她自己的语气汇报。

结束原因只有这几种：`timeout`（到点）、`login-wall`（撞登录/验证码）、`hdc-lost`（线和设备掉了）、
`give-up`（可恢复的失败攒够 12 次）、`done`（主人喊停或少量合法提前结束）。

### 失败分两种，别一种就把整轮掐死

- **可恢复**（记一次错就继续）：清单里没这一条、坐标过期点了没反应、模型没给合法 JSON、动作被红线拒。
  上限 `maxRecoverable`（默认 12）。
- **致命**（直接结束）：hdc 连不上/超时（连续 3 次）、`/手机 停`、撞登录墙。

App 漂移也不结束：连续 2 步发现前台不是目标 App，就用命令把她拉回来继续玩。

### 红线

- **任何情况都不做**：付款、下单、转账、红包、充值、提现、删除、卸载、注销、退出登录、恢复出厂。
- **对外发言默认关闭**：评论、发消息、关注、点赞、收藏、转发。只有主人这一轮明确要求、并且面板里
  「允许她自己在手机上发评论/发消息」是开的时候，才会做。
- **碰到登录 / 验证码 / 人脸 / 指纹就停**，不尝试绕过。
- 单次最多 30 分钟，随时可以 `/手机 停`。

## 会访问哪些网址

**一个都不访问。** 模块不联网、不上传截图、不下载任何东西：

- 手机那头只有本机的 `hdc` 进程（USB 或你已连好的无线调试）；
- 截图和控件树只落在本机数据目录（`plugins-data/aurabot/modules-data/screen/`），最多留 3 张；
- 跟她聊天走的是插件自己的 QQ 网关，和本模块无关（本模块只调用插件给的 `api.*`）。

## 设置项

| 键 | 说明 |
|---|---|
| `hdc` | hdc 可执行文件路径，留空自动找 |
| `sn` | 设备 SN，留空取第一台；多台都连着时必须填 |
| `wake` | 操作前先 `power-shell wakeup` |
| `allowShellLaunch` | 允许用后台命令兜底（关掉就只走点图标） |
| `preferCommandOpen` | **新**：优先用命令开应用（默认开）。关掉 = `human` 档 |
| `allowForceStop` | **新**：允许 `aa force-stop`（默认开，面板可关） |
| `allowPost` | 允许她在手机上做评论/发消息等对外动作（默认关） |
| `stepMs` | 自动玩时每步间隔（默认 4500ms） |
| `dumpEvery` | **新**：每多少个动作读一次屏（默认 3） |
| `playMinutes` | 没说时长时默认玩几分钟 |

面板上还能看到「进度」（步数 / 帧数 / 剩余秒）和「最近走的几步」，出问题一眼能看出是哪一步卡住的。

还有三个**不进面板**的内部旋钮，写在 `index.mjs` 的 `defaults` 里，要改直接改文件：
`doneGraceRatio`（剩余时间超过总时长这个比例时无视 `done`，默认 0.3）、
`minSteps`（步数少于这个数时无视 `done`，默认 8）、
`maxRecoverable`（可恢复失败的上限，默认 12）。

## 已知限制

- 只支持**一台**设备（多设备的接口留着 `sn` 字段，逻辑没做全）。
- 控件树是「无障碍节点」的视图，纯图形界面（视频画面、绘画画布）它读不到，得靠截图人看。
- 桌面只有一屏时「翻屏找图标」会立刻判定到底，然后走下拉搜索；搜索页的措辞随系统版本可能不同。
- HOS7 的全局搜索页是「从桌面拉下来的一层」，**Home 和 Back 都退不出去**，模块会自动往上滑把它收回去。
- 系统级弹窗（例如「暂无可用打开方式」）会把整棵控件树盖成只剩几个节点，模块会先点掉
  「知道了 / 取消 / 跳过」这类按钮再看屏；**「允许 / 同意」不在自动点掉的名单里**，权限弹窗留给你自己决定。
- 截图走 `snapshot_display`，比 `uitest screenCap` 快很多，但要求设备端支持这个命令（HOS 5+ 都有）。
- `uitest` 的部分能力跟系统版本有关（`uiInput text` 从 API 18 起才有）。如果手机版本低，
  打字会自动退回「点坐标 + inputText」。
- `aa start` 拉起、或主人自己打开的 App，退出时**不会**自动 force-stop，免得把她自己开着的东西也关了。

## 测试

```sh
node --test test/unit.test.mjs   # 纯逻辑单测：控件树解析、序号点击点、JSON 抽取、批量动作、done 忽略、帧对比、红线
node test/live-check.mjs         # 真机联调：状态 → 读界面 → 打开计算器 → 回桌面
node test/live-check.mjs cmd 抖音 # 只验命令层：start → state → stop → state
node test/live-check.mjs open 快手 # 只验打开某个 App（会打印走的是命令还是人手）
node test/live-play.mjs 1        # 真机跑一轮「自动玩 1 分钟」（假模型，含「提前喊收工被无视」的用例）
```

`live-check.mjs` 用一个假的 `api` 把 `index.mjs` 加载起来，直接调工具，适合排查
「到底是模块的问题还是手机的问题」。`live-play.mjs` 用假模型保证结果可复现，
一轮 1 分钟大约 18 步、读 6 帧，可以拿这个比例看「是不是又变成每步都读屏了」。
这两个脚本一开头会先问 `hdc list targets`：没有设备就打印一行提示、以 0 退出，
所以在别人的机器或 CI 上跑全量测试不会因为它们变红。
