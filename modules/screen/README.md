# 手机屏幕（screen）

让她在主人的鸿蒙手机（HarmonyOS NEXT / 5 / 6 / 7）上长出一双手：看一眼画面、读界面文字、
点、滑、打字、按键，还能像人一样从桌面点开任意 App。更进一步：说一句「去玩十分钟手机」，
她真的会自己挑个 App 玩十分钟，然后回来汇报。

底层走 **hdc**（HarmonyOS Device Connector，鸿蒙版的 adb）。鸿蒙没有 adb，hdc + 设备端
`uitest` 就是官方那套 UI 注入能力。

## 需要什么

| | |
|---|---|
| 插件 | Aurabot ≥ 1.2.0（扩展接口 v1） |
| 电脑 | 装了 hdc：DevEco Studio / Command Line Tools 里的 `hdc.exe`；留空会自动找 |
| 手机 | 开发者模式 + USB 调试打开，插上后 `hdc list targets` 能看到设备 |
| 账号 | 只有**主人私聊**能用这套工具，群友拿不到手机 |

## 怎么用

装好模块后在面板「已安装」页看到「手机屏幕」，把 `hdc` 路径填上（或者留空让它自己找）。

主人私聊里可以直接说人话：

- 「看一眼我手机现在什么界面」→ 截图发到聊天里
- 「把抖音打开」→ 她去桌面点图标；桌面没有就滑屏找，再没有就下拉搜索搜「抖音」点结果
- 「帮我点一下那个搜索框，输入天气」→ 读界面 → 点 → 打字
- 「去玩十分钟手机」→ 她去玩，十分钟后回来汇报
- 「别玩了」→ 立刻回桌面

也支持手打命令（只认主人）：

```
/手机            截图
/手机 状态        连接 / 型号 / 前台应用
/手机 桌面        回桌面
/手机 开 抖音     打开应用
/手机 玩 10 抖音  去玩十分钟抖音
/手机 停          停止自动玩
```

## 她拿到的工具

| 工具 | 干什么 |
|---|---|
| `screen_see` | 截图并发到聊天里 |
| `screen_layout` | 把当前界面读成文字清单（`序号. 文字 [可点] @坐标`），可按关键词过滤 |
| `screen_tap` | 点：按文字、按清单序号、或按比例坐标 |
| `screen_swipe` | 上/下/左/右滑，可连滑、可快滑 |
| `screen_type` | 往输入框打字（可先点坐标） |
| `screen_key` | Back / Home / Power / KeyCode |
| `screen_open` | 打开 App（点图标优先，后台指令只做兜底） |
| `screen_status` | 连接、型号、系统版本、前台应用、是否在自动玩 |
| `screen_play` | 自己去玩一段时间，到点回来汇报 |
| `screen_stop` | 立刻停止并回桌面 |

## 「去玩十分钟」是怎么跑起来的

一轮 QQ 对话等不了十分钟，所以 `screen_play` 是**模块里的后台会话**，不占对话：

1. 先用「点图标」的方式把 App 打开（桌面 → 翻屏 → 下拉搜索 → 兜底后台指令）；
2. 之后每隔 `stepMs`（默认 9 秒）：读一次控件树 → 问一次模型「下一步做什么」→ 执行 → 记录；
3. 到点（或踩红线、或连着失败三次）就停：按 Home 回桌面 → 用她自己的语气生成汇报 → 发到发起的那次聊天。

### 红线

- **任何情况都不做**：付款、下单、转账、红包、充值、提现、删除、卸载、注销、退出登录、恢复出厂。
- **对外发言默认关闭**：评论、发消息、关注、点赞、收藏、转发。只有主人这一轮明确要求、并且面板里
  「允许她自己在手机上发评论/发消息」是开的时候，才会做。
- **碰到登录 / 验证码 / 人脸 / 指纹就停**，不尝试绕过。
- 单次最多 30 分钟，步数有上限，随时可以 `/手机 停`。

## 会访问哪些网址

**一个都不访问。** 模块不联网、不上传截图、不下载任何东西：

- 手机那头只有本机的 `hdc` 进程（USB 或你已连好的无线调试）；
- 截图和控件树只落在本机数据目录（`plugins-data/aurabot/modules-data/screen/`），最多留 3 张；
- 跟她聊天走的是插件自己的 QQ 网关，和本模块无关（本模块只调用插件给的 `api.*`）。

## 设置项

| 键 | 说明 |
|---|---|
| `hdc` | hdc 可执行文件路径，留空自动找 |
| `sn` | 设备 SN，留空取第一台；多台都连着时必须填 |
| `wake` | 操作前先 `power-shell wakeup` |
| `allowShellLaunch` | 只在桌面和搜索都失败时才用 `aa start` 兜底 |
| `allowPost` | 允许她在手机上做评论/发消息等对外动作（默认关） |
| `stepMs` | 自动玩时每步间隔（4~30 秒） |
| `playMinutes` | 没说时长时默认玩几分钟 |

## 已知限制

- 只支持**一台**设备（多设备的接口留着 `sn` 字段，逻辑没做全）。
- 控件树是「无障碍节点」的视图，纯图形界面（视频画面、绘画画布）它读不到，得靠截图人看。
- 桌面只有一屏时「翻屏找图标」会立刻判定到底，然后走下拉搜索；搜索页的措辞随系统版本可能不同。
- HOS7 的全局搜索页是「从桌面拉下来的一层」，**Home 和 Back 都退不出去**，模块会自动往上滑把它收回去。
- 系统级弹窗（例如「暂无可用打开方式」）会把整棵控件树盖成只剩几个节点，模块会先点掉
  「知道了 / 取消 / 跳过」这类按钮再看屏；**「允许 / 同意」不在自动点掉的名单里**，权限弹窗留给你自己决定。
- 截图走 `snapshot_display`，比 `uitest screenCap` 快很多，但要求设备端支持这个命令（HOS 5+ 都有）。
- `uitest` 的部分能力跟系统版本有关（`uiInput text` 从 API 18 起才有）。如果手机版本低，
  打字会自动退回「点坐标 + inputText」。

## 测试

```sh
node --test test/unit.test.mjs   # 纯逻辑单测：控件树解析、序号点击点、JSON 抽取、红线过滤
node test/live-check.mjs         # 真机联调：会真的去点手机（先确认手机在你手上）
node test/live-play.mjs 1        # 真机跑一轮「自动玩 1 分钟」（假模型，结果可复现）
```

`live-check.mjs` 用一个假的 `api` 把 `index.mjs` 加载起来，直接调 `screen_status` /
`screen_layout` / `screen_open`，适合接线的时候排查「到底是模块的问题还是手机的问题」。
